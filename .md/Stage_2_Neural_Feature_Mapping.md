# Stage 2 — Neural Feature Mapping
## Interactive Skills & Architecture Concept

### Core Recommendation

Use **Option 2 — Live Feature Weight Pulse** as the foundation, but upgrade it into a more distinctive **Neural Feature Mapping** system.

The section should not behave like a traditional skills grid.

> **Every major skill is mapped to a specific 3D neural-layer cluster.**

Hovering a skill activates its assigned nodes and connections. Clicking a skill temporarily expands and isolates its neural cluster, showing how that technology fits into the larger AI architecture.

This makes the Skills section feel like a real engineering system rather than a list of technologies.

```text
  ↓

  ↓

  ↓
```

```text

 ↓

 ↓

 ↓
```

```text
 ↓

 ↓

```

```text

 ↓
```

```text
 ↓
cluster expands
 ↓
technical architecture appears
 ↓
other clusters dim
 ↓
user closes / changes selection
 ↓
return to normal state
```

# 12. Visual Style

Aim for:

```text
AI Research Interface
        +
Neural Architecture
        +
Interactive Data Visualization
        +
Modern Portfolio UI
```

Recommended:

- Soft node glow
- Controlled particle pulses
- Thin connection lines
- Depth
- Subtle glass panels
- Small technical readouts
- Smooth camera motion
- Layer highlighting

Avoid:

- Excessive neon
- Too many floating cards
- Constant particle explosions
- Random motion
- Decorative effects with no semantic meaning

```javascript

  Python: {
```

Keep these mappings centralized rather than hard-coding them inside UI components.

# 17. State Architecture

Keep interaction state separate from the 3D renderer.

```text
Skills.jsx
    │
    ├── hoverSkill
    ├── selectedSkill
    └── activeLayer
          │
          ▼
       AIWorld
          │
          ▼
   SkillCluster / NeuralCore
          │
          ▼
   node activation + glow
```

Do not recreate the 3D scene when the selected skill changes.

Only update the relevant node states.

---

# 18. Performance Rules

Because the neural network persists through the whole portfolio:

```text
ONE neural scene
ONE points system
REUSABLE geometries
REUSABLE materials
NO scene recreation on skill hover
```

On hover:

```text
update node intensity
update connection intensity
update active cluster
```

Do not create new meshes every time a user moves the mouse.

---

# 19. Accessibility / Fallback

The skill information must remain understandable without WebGL.

HTML should still contain the skill names and categories.

WebGL enhances the information; it should not be the only way to discover it.

# 21. Prompt for the Implementation Agent

> **Create Stage 2 as an interactive “Neural Feature Mapping” system rather than a traditional skills grid. Use the persistent 3D neural network from Stage 1 and reorganize it into four conceptual layers: Core/Input, Processing/ML, Intelligence/AI, and System/Engineering. Map every major skill to a specific 3D node cluster using centralized data configuration. Hovering a skill should temporarily illuminate its assigned cluster, pulse its connections, and show a compact technical information panel. Clicking a skill should temporarily isolate and expand its cluster while revealing a simplified architecture relevant to that technology. Keep hover and click state separate and do not recreate or remount the Three.js scene during interaction. Use semantic layer colors, smooth GSAP/camera transitions, reusable Three.js geometries, and a fully readable HTML fallback. The result should communicate that the listed skills are components of one real engineering system rather than a conventional technology list.**
